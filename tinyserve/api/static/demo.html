    Read these numbers as behaviour, not as benchmarks.
    Browsers cap concurrent connections per origin (~6 on HTTP/1.1), so a large burst does not
    all reach the server at once — later requests wait in the browser, before admission control
    ever sees them. That inflates TTFT here and under-counts rejections compared with
    benchmarks/burst.py. TTFT shown is measured in the browser and includes paint; the
    server's own ttft_seconds histogram is the accurate one. Published measurements live
    in docs/benchmarks.md. Every card is one POST /generate with
    stream: true — the same request curl -N makes.
